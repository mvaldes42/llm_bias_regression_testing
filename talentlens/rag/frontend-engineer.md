# Role profile — Door to Door mid-level web engineer

Kilometer Engineering. Internal. Pair with the careers posting.

## Seat

Mid-level (about 3–5 years). You are the main web engineer on Door to Door: passenger and driver web for this initiative, plus a seat in the Front-End Web Engineering Chapter.

You are not a junior (someone else should not have to slice every ticket). You are not staff or tech lead (you do not set org-wide architecture or run the chapter). A path toward lead exists later; it is not this hire.

## Ownership

**You own**

- Features in this product slice from spec with PM/PD through production: UI, the Node/NestJS you need for the ~60/40 split, tests, and the monitoring on that path
- Quality of what you merge: coding standards, Kilometer architecture guidelines, review comments that others can act on
- Mentoring the engineer ramping on web (pairing, review, unblocking) — a share of your time, not the whole job
- Showing up to the Front-End Chapter: adopt shared libraries and standards; bring problems from Door to Door; you do not have to lead the chapter
- Saying when a design or API will not scale, and proposing a slice that still ships

**You share / escalate**

- Cross-team contracts and platform changes (auth, design system, core APIs) — you integrate with what exists; you do not rewrite it alone
- Staff-level architecture and VP-level roadmap
- Production incidents outside your slice; you still join if Door to Door is involved

**Autonomy**

High inside the squad. You can merge behind review, talk directly to PM and design, and sequence work. You do not wait for a tech lead to start a well-specified story. You do not silently change another team’s service.

## What we expect week to week

- TypeScript, React, HTML, and CSS in production: components, state, data fetching, responsive layout, design-system usage
- Git, Docker, enough Node to own your backend share, basic observability
- Tests and CI on the path you touch; Friday time used for named debt, performance, or documentation — not only new features
- Design and code review both ways
- English with PM, design, and other engineers; trade-offs explained without a deck
- Org-standard AI coding tools, with review (no secrets in prompts, no unreviewed dumps into main)

Nice-to-haves on the posting (SEO, extra NestJS, Kubernetes, native mobile) are growth areas, not the job definition.
